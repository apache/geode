# GEODE-10531 — preserve subprocess permission behavior during warning cleanup

Public issue: https://issues.apache.org/jira/browse/GEODE-10531
PR: https://github.com/apache/geode/pull/7971
Owner: Sai Boorlagadda. Status: revised proposal, not merged or approved.

## Correction and proposed scope

The original ticket says SecurityManager was removed in Java 21. It remains there,
deprecated for removal; the original method compiles with removal warnings. This is a
warning/compatibility decision, not the claimed missing-API Java 21 blocker.

`OSProcess.bgexec` checks the requested executable before constructing a shell command.
`ProcessBuilder.start()` subsequently checks the shell (`bash` or `cmd.exe`). Removing the
first check changes configured SecurityManager policy. OS permissions do not replace that policy.

This revision retains the explicit check and suppresses `removal` only on its local variable
declaration. It preserves existing behavior while allowing this statement to compile with
removal warnings enabled. It does not enable the globally suppressed warnings or finish 10479.
The suppression must be revisited when legacy SecurityManager support is explicitly retired.

The community still needs to agree this exception and revise the issue's acceptance criteria,
which currently require removing all SecurityManager references. No such approval is implied.

## Proposed acceptance criteria

- Preserve a configured manager's denial of the requested executable before shell launch.
- Preserve normal launch without a SecurityManager.
- Avoid removal warnings at this compatibility statement on Java 17 and 21.
- Keep the suppression local and explain why ProcessBuilder is not equivalent.
- Validate with a separate-JVM regression test; do not install a manager in the test worker.
- Record the agreed exception/retirement policy and update the public issue and PR description.

The regression test is `OSProcessSecurityIntegrationTest`. Its denied-target case fails if
only the shell is checked; its no-manager case verifies a child JVM produces version output.
This is focused process coverage, not proof of a full Geode build or JMX integration.
